# 给长期记忆一层会过期的现在

> `today_set × ctx_set`：一个很小的 Living Context。

做这个项目，是因为一件有点荒唐、又反复发生的事。

妈妈来我这儿住了一阵。我说「我妈要回家了」，模型记住了这句话，却没有一个合适的位置存放“正在发生、之后会改变”的状态。于是妈妈明明还在，它已经开始说她走了；等她真的回去，那条“妈妈还在这儿”又迟迟不肯退场。

它并不是完全忘了，甚至可以说记得太认真。问题是，长期记忆擅长保存已经发生的痕迹，却不擅长保存一个**暂时成立的现在**。

于是有了 Living Context。

## 三种不同的“记住”

我把信息分进三个地方：

- **痕迹**：那天确实发生过，以后也不会变。放进长期记忆。  
  例如：「妈妈来看过我。」
- **当天**：只在今天有效，天亮就可以清掉。放进 `today_set`。  
  例如：「今天中午吃了炖牛尾骨。」
- **状态**：会持续几天或一阵子，但终究会改变。放进 `ctx_set`。  
  例如：「妈妈这段时间在我这儿。」

同一件事可以同时留下三种记录，但它们不能混在一起。发生过的痕迹可以一直保存；今天的小事不必活过天亮；暂时的状态则需要过期、复核和退场。

判断标准也很简单：

> 不是“这件事值不值得记”，而是“过一阵再问一遍，会不会让人觉得烦”。

会烦的，就应该有一个地方先放好。

## `today_set × ctx_set`

`today_set` 管今天。它适合睡了多久、吃过什么、正在赶哪一项作业——天亮后自动清理，不污染长期记忆。

`ctx_set` 管一段时间内仍然成立的背景。每条状态可以带复核时间：

1. **fresh**：仍在有效期内，可以直接使用；
2. **stale**：到了复核日，记得它曾经成立，但使用前应该先确认；
3. **drop / archive**：确认已经结束，退出当前上下文，并留下“它已经不成立”的墓碑，避免旧摘要把它重新捡回来。

它们不是两套彼此独立的小工具，而是一层完整的“现在”：今天的事由 `today_set` 接住，跨天但会变化的事由 `ctx_set` 接住，再和真正的长期记忆各自守住边界。

## 换窗口，也不用重新说一遍

同一份状态可以被不同入口共同读取：官方客户端、自建 API、长会话 SDK，都从同一份 Living Context 里拿到当前背景。

在普通 API 路线里，只有刚发生变化、还没进入摘要的内容才做增量注入，尽量不破坏缓存；在长会话 SDK 路线里，则用快照回执判断同一份内容是不是还留在上下文中——还在就不重复发送，被 compact 掉了才补回来。

所以，换 session 不等于把今天重新讲一遍；长会话也不会因为每轮重复注入同一张小纸条而越来越胖。

## 它不会做什么

Living Context 不是第二个庞大的记忆库，也不替模型决定什么值得永久保存。

它只负责一件很小的事：让“此刻仍然成立”有边界、有期限，也有离开的方式。

它不会拿背景主动找话题，不会因为读到状态就反复提起；`stale` 也不等于错误，只代表“过去记过，现在先问一句”。一条已经过期却仍被当真的状态，往往比什么都没记更糟。

## 开源内容

仓库里放了一个只依赖 Python 标准库的参考实现，包括：

- `today_set / today_get`
- `ctx_set / ctx_get / ctx_drop`
- 到期降级、七天缓冲、归档与墓碑
- API 路线的增量注入与摘要同步
- SDK 路线的快照回执与按轮撤销
- 五个 MCP 工具定义与配套 prompt

它不是强制协议，只是一份可以拆走、改名、接进自己系统里的实现。

项目地址：[Cerie-r/still-true](https://github.com/Cerie-r/still-true)
