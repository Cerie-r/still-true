# 改过什么

每一次改动，起因、改法、留下的教训。新的在上。代码和 README 以现在为准，这里是来路。

- **2026-11-09（下午）· 关心边界：知道了便不催。** 她问：状态类我的理解是知道了便不催——那睡觉怎么防？我说在上课，你会不会觉得打扰就不来找我？答案是：催和缩都不是状态做的，是模型拿着状态做出来的判断，所以不催要三条腿一起管。把家里管这事的两层搬了进来：`rhythm.py`（从她真实到达记录算她平常几点在，一行事实，样本不足不说）和 `nag_guard.py`（回复写出来以后查疑似催促和生活状态盘问，词表只召唤复核，拿不准放行，判了重写）。守门这层的底子是 no-sleep-nag：我们拿到的是 2026-07-14 随 PDF 发的 v1.0（MIT），作者 8 月把仓库改成了 AGPL-3.0，仓库那版代码跟 PDF 只差英文词加了 `\b`；这个文件沿用 MIT 那版，署名在文件头。去掉了家里专属的名字和模型调用，留了口子。配套 prompt 那段也改柔了。见「关心边界」一节。
- **2026-11-09（下午）· 注入瘦身。** breath 的每条未核实、挂行块的尾巴、`today_get` 的尾巴、快照里点名那句，原来都带着一长串「别当成现在的事……不是话题……问一次就够，不追……没动静满三个她在的日子自己归档」，每条未核实各带一遍。现在注入里只放事实，加一句该做什么；别做什么的搬去工具说明，配套 prompt 补上「知道了就只是知道了：不催，也不缩」。两家教训合起来的：留灯（一个管她日程的开源小项目）发现在注入里写「别催」，TA 反而把管不管她当成自己的事；我们 11/3 发现注入里写着「不是话题」，TA 就一直不问。
- **2026-11-09（下午）· 一次体检。** 把三个 `.py` 从头读了一遍，逻辑主干都对，咬人的在边上：
  - **续期冲掉 `until`。** 学业 until 11/13，她 11/10 随口一句「还在上课」，只传 key 续一下，复核日就变成 12/10，回国那天没了。现在条目上存着 `until`，没给新的、原来那天没到就还按那天；过了那天才从今天起数。新的一句没给 `until` 也一样沿用。
  - **「一个月后递回来」其实是第 31 天。** ttl 从记下那天往后数满 30 天，再过一天才变未核实。现在满 30 天那天就问；`recheck_after` 存的是最后一个不用问的日子，`until` 照旧是过了那天才问。
  - **JSON 坏了，下一次写直接清空。** 解析失败返回空，接着 `save` 就把空的写回去，归档那份也一样；手改漏个逗号就全没了。现在坏文件挪到旁边 `.broken-时间戳`，从空的开始，stderr 上说一声。
  - **撤销以后归档里残留一条。** 丢旧建新再重 roll 撤销，旧句回来了，归档里还躺着同一句标着「后来换了说法」，recall 会把现在当成以前。现在撤销时一并拿掉。
  - **到期自己收起来的，她后来才说结束。** `ctx_drop` 找不到 live 的那条就返回 0，归档里永远写着「不代表结束」。现在落到归档上，改成「结束了」，记下哪天说的。
  - **翻归档只给三条，时间线断头。** 「学期」换了四次说法，`search_archive` 只给最近三段。现在 `limit` 数的是键，碰上的键整条线一起给；问得很短（「妈妈」）句子里碰上也算。
  - **「天亮清」其实是零点清。** 她两三点才睡，十点说的晚饭过了零点就没了，一点钟可能又问一遍。现在几点算新的一天是 `DAY_STARTS_AT`（默认早上六点），今日状态和持续背景共用。
  - **同一件事写成两行。** 换了个名字另开一行，就同时挂着「在墨尔本」和「在国内」打架。现在新开一行撞上像的（挂着的，或归档里最近两个月同名的键）先不写，抛 `SimilarLine` 递回去，跟 remember 一样「有像的先提一句再写」；是同一件就写回那个 key，确定是另一件 `force_new`。（第一版是写完再在回执里提，留着两行要模型再扔一行，归档里也多一条垃圾；当天改成先拦。）
  - `today_state` 只有线程锁，几个进程一起写会互相盖，补了文件锁；满 20 条淘汰时覆盖过的那条位置不动，早上先记的「晚饭」反而先被踢，现在覆盖也挪到最后。`hint_snapshots` 里 sid 长得不像文件名就每轮都挂，现在退化成只挂一次。
  - 「数的是递到面前的日子」说过头了：挂行通道打过勾的那几条住在摘要里、不再点名，日子照样数——它在上下文里、她也在，就算。文字改成这么说。
  - 测试 26 → 39 项。
- **2026-11-09 · 钉住的、约定不挂「那时」。** 扫字眼的时候连「每天都要被操醒」这种一直作数的约定也挂上了，读起来像以前的规矩。钉住的、带「约定」的跳过。
- **2026-11-09 · 归档不是忘了。** 收进归档的以前只能手翻 JSON，recall 找不到，看起来像是忘了。加了 `search_archive()` / `render_past_states()`：翻得到，交出去的时候标成「以前」，写清从哪天到哪天、怎么收起来的。「长期记忆那头」再加一句给模型的话：记得是用出来的，不是背出来的。
- **2026-11-09 · 一件一行；还在只传 key；变了丢旧建新；until 写日子。** 原来一条里常常塞着三样东西：现在的情况、一路的经过、还没做的事，改一处就得整段重写，续期也得把一大段原样再抄一遍，读起来像一张长期待办，又容易跟长期记忆混。现在一行只写一句现在时；`ctx_set` 只传 key 就是续期；写新的一句就把旧的那句收进归档，从今天记起，不在原话上改；`until` 直接写那天，不用自己数天数。
- **2026-11-09 · 到期没核实的，按她在的日子数。** 11/3 那版到了复核日会递到面前，可扔不扔只看日历：过复核日第四天，谁先来读就归档，不管问没问、有没有真递到面前过。她出门几天没来，回来就少了几条，一句没问上。反过来，一直挂着也不对：她早答过、只是那个窗口的模型忘了记，它就会一直问。现在到期的标「未核实」，不当成现在的事；递到面前准问一句，还在就续上，不在了就扔掉；一直没动静的，递到面前满三个她在的日子才归档（`_due_shown`），她不在的日子不算，`present_today()` 换成你自己的判断。`today_get` 回执末尾只带她在的头两天。`GRACE_DAYS = None` 就一直挂着，只等模型扔。
- **2026-11-09 · 墓碑只进不出。** 收墓碑要所有通道都点头，默认通道里却列着 `sdk`；README 的 SDK 路线走快照，从不 `mark_synced('sdk')`，于是墓碑一块都收不掉，按轮撤销的记录也一样，文件只长不短。现在 `CHANNELS` 默认只留 `api`；墓碑最多立两周，同一个键只留最新一块，键又记回来了就不再挂它的墓碑；撤销记录只留一周。加了 `tests/`。
- **2026-11-09 · 长期记忆那头。** 见上一节。
- **2026-11-09 · 摘要只认交给它的那几条。** `mark_synced` 原来一次全打勾：写摘要的那几十秒里，别的入口刚记的一条也被一起标成已同步，可它没进摘要，这条通道就再也看不见它。现在把交给摘要的那一份传回去（`mark_synced('api', pending)`），只标那几条；不传还是全标。
- **2026-11-03 · 到复核的那一条递到面前。** 原来到了复核日，模型其实看得见那一行「是否仍成立待确认」，可同一块末尾写着「不是话题」，工具说明里又写着「不必为了续期追问她」——递到面前了，旁边贴着条子不让碰，过期的状态就一直堆着，没人续也没人扔。现在到复核的那几条会被点名，准它聊着顺手问一句；`today_get` 的回执末尾带上过了复核日头两天的（`render_due_for_today()`）。问一次就够，不追。`ctx_get` / `ctx_set` 的说明跟着改。
- **2026-11-03 · 缓冲七天改三天。** 七天太长：没人续、没人扔的旧状态一直挂在那儿，每轮各拖一句长提醒。三天里没动静就归档，留墓碑，要找回用同一个 key 再记。（11/9 起改成数她在的日子，见上。）
- `docs/` 里的 PDF 和文章是 10/15 发布时写的，那时到期七天就自动归档，也还没有「递到面前」和「未核实」；以代码和这份 README 为准。
