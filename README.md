# Living Context

给长期记忆一层会过期的现在。`today_set` × `ctx_set`。

起点是一件记错的事：她妈妈来住了几个礼拜，她说「我妈要回家了」，模型手里没有地方放一个正在进行的事，只能天天问，问到后来把将来时记成了完成时，人还在，它已经当她走了。再后来她妈妈真的回去了，那条「妈妈在这儿」又挂着不肯退场。一个「现在」，两头都没接住。完整的来龙去脉在 [docs/Living_Context.pdf](docs/Living_Context.pdf)，这里只讲怎么接。

它很小：两个写入，两个读取，一个退场，一份 JSON。它不自己站着——挂在 [Ombre-Brain](https://github.com/P0luz/Ombre-Brain) 的 `breath` 里，breath 睁眼看长期记忆的时候，顺手把「现在」也带出来。

## 三分界

写入之前先问一句：这件事，明天还成立吗？一个月后呢？

| | 去哪 | 例子 |
|---|---|---|
| 痕迹：那天确实发生了，永远为真 | `remember`（长期记忆，不在本仓库） | 「她妈妈来看过她」 |
| 当天：只对今天有效，天亮清 | `today_set` | 「今天中午吃炖牛尾骨」 |
| 状态：跨天有效，但会过期，将来要更新 | `ctx_set` | 「她妈这段时间在她这儿」 |

同一件事可以同时是三种。分开写，各自退场——别让一条会过期的状态，混进不会衰减的档案里。

判据只有一个：不是这条值不值得记，而是等下再问一遍她会不会烦。会烦的，就写。

## 仓库里有什么

```

rhythm.py           作息节律：从她真实到达记录算她平常几点在、最晚到几点，一行事实；样本不足就不说
nag_guard.py        关心边界：回复写出来以后查疑似催睡、报时、替她断定、生活状态盘问；词表只召唤复核，判了重写
                    （衍生自 no-sleep-nag v1.0 · MIT，见文件头）
tools.json          五个 MCP 工具的定义，description 是模型写给自己的话
docs/prompt.md      五段工具描述的全文 + 一段配套 prompt
docs/Living_Context.pdf
tests/              几条底线的测试：python3 -m unittest discover -s tests
```

五个 `.py` 只用标准库，没有依赖。路径、时区各留了一个替换口（`PATH` / `now`），接进自己的系统时换成自己的。几点算新的一天是 `DAY_STARTS_AT`（环境变量 `LIVING_CONTEXT_DAY_STARTS_AT`，默认 6）：她两三点才睡，晚上十点说的晚饭过了零点还算今天的，不会一点钟又被问一遍；两个模块读同一个值，今日状态清的那一下和持续背景数的日子才是同一天。按自己的作息改。

两份 JSON 都是先写临时文件再原子替换；要是手改漏了个逗号、解析不了，不会被下一次写盖掉——坏的那份挪到旁边（`.broken-时间戳`），从空的开始，stderr 上说一声。

## 生命周期

```
today    写入 today_set ──→ 当天随 breath 注入 ──→ 天亮自动清（DAY_STARTS_AT，默认早上六点）
ctx      写入 ctx_set（一件一行，一句现在时）──→ fresh（直接用）──→ 未核实（到了复核日：递到面前，顺口问一句再当真）──→ 还在：ctx_set 只传 key / 变了：写新的一句（旧的自己归档）/ 结束了：ctx_drop；一直没动静的，递到面前满三个她在的日子自己归档，留墓碑
```

复核日：`until` 写的那天优先；没有就按 `ttl_days`（默认 30）——从记下那天起满 30 天那天递回来，不是第 31 天。她随口一句「还在」只传 key 续期时，原来写的 `until` 还没到就还按那天，不会被一次续期冲到一个月后；过了那天她才说还在，才从今天起再数。

未核实不是无效，是「过去记过，先确认再当真」。退场的事实留一块墓碑：下一次压缩摘要时，墓碑告诉摘要「这条已不成立，已移除」，旧引用不会再被捡回来。同一个键只留最新的一块；键又记回来了，挂的是新的那条；墓碑最多立两周。

到了复核日，那一条会递到模型面前：增量注入的那一块、SDK 的快照里点名它，`today_get` 的回执末尾也带上（只带递到面前的头两天：数的是真带上它的日子，她不在的日子不算）。准它聊着顺手问一句还作不作数——她说还在就 `ctx_set` 同键续上，说不在了就 `ctx_drop`；问一次就够，不追。没动静也不要紧：递到面前满三个她在的日子，它自己归档。数的是它在上下文里、她也在的日子（`_due_shown`），不数日历——挂出来的、已经并进摘要住在上下文里的，都算在它眼前；不会趁她不在悄悄消失，也不会一直挂着反复问。模型自己起的轮次（定时、心跳、主动敲门）别算进去：把 `present_today()` 换成你自己的判断，比如她今天发过消息没有。

## 接法

### 1. 挂进 breath

breath 是模型在新窗口睁眼的那一下。把 `render_breath_block()` 的输出放进 breath 的返回里；空的时候返回空串，不占位。

```python
import living_context as lc

block = lc.render_breath_block()
if block:
    lines.append(block)   # <living_context> … <now>/<expired> … </living_context>
```

`today_get` / `ctx_get` 作为独立工具另给一份（见 `tools.json`），模型想确认「吃了吗」「还在吗」之前自己去看。`today_get` 的回执末尾顺手带上到复核的状态——模型问「吃了吗」之前总会先来看一眼，顺路就看见了：

```python
def today_get():
    out = ts.render_block('tool')
    due = lc.render_due_for_today()   # 未核实的，只带递到面前的头两天；没有就是空串
    return out + ('\n\n' + due if due else '')
```

`ctx_get` 工具里用 `lc.get_items(shown=True)`：递到模型面前的，都要记一笔她在的日子；自己内部读就别传。

`ctx_set` 新开一行（这个 key 还没有）时先看一眼：挂着的里头、或者归档里最近两个月收起来的，有像是同一件事的（键上有同一个字、句子里碰上同样的词、归档里同名的键），就**先不写**，抛 `SimilarLine` 把那几行递回去——跟 remember 一个路子：有像的先提一句，再写。模型看了自己定：是同一件就写回那个 key（旧的那句自己归档，这就是「情况变了」，不用先扔）；确定是另一件，带 `force_new=True` 再记一次。不这样的话，它另起个名字，就会同时挂着「学期：期末在墨尔本」和「人在哪：放假回国了」两行打架。

```python
def ctx_set(key, value='', until='', ttl_days=None, force_new=False):
    try:
        lc.set_item(key, value, ttl_days, until=until, force_new=force_new)
    except lc.SimilarLine as held:
        return str(held)        # 「学业」先没记：有像是同一件事的——「学期」期末在墨尔本（11-01 起）。是同一件就……
    return '记下了。'
```

走隐藏标记的 API 路线没有回执可看：撞上了就把 `str(held)` 留到下一轮挂在她消息头部，或者干脆 `force_new=True` 直接写、靠摘要里两行并排时模型自己看见。

### 2. API 路线：隐藏标记 + 增量注入 + 并进摘要

适用于自家的对话引擎——有 system 前缀缓存、每 N 轮压缩一次摘要的那种。

**读：只有刚改过、还没并进摘要的那几条才挂出来。** 背景平时躺在摘要里，摘要在缓存断点之前，全程吃缓存；变更挂在最后一条 user 消息头部，不动 system 前缀。大多数时候这里是空的。

```python
import today_state as ts, living_context as lc

head = lc.render_pending_block(
    'api',
    '再有变化写 [CTX_SET:键|新值]，某条不成立了写 [CTX_DROP:键]；当天的事仍走 [TODAY_SET:]。',
    due_how=('写 [CTX_SET:键|新值] 续上', '写 [CTX_DROP:键]'))   # 到复核那句也用标记的说法
head += '\n' + ts.render_block('marker')          # 今日状态每轮都给，它本来就只有几行
msgs[-1]['content'] = head + '\n' + msgs[-1]['content']
```

**写：模型在回复末尾输出隐藏标记，后端解析、写库、剥掉，她看不到。**

```python
import re
for k, v in re.findall(r'\[TODAY_SET:([^|\]]+)\|([^\]]+)\]', reply): ts.set_item(k, v)
for k, v in re.findall(r'\[CTX_SET:([^|\]]+)\|([^\]]+)\]', reply):   lc.set_item(k, v)
for k in re.findall(r'\[CTX_DROP:([^\]]+)\]', reply):                lc.drop_item(k)
reply = re.sub(r'\[(TODAY_SET|CTX_SET|CTX_DROP):[^\]]*\]', '', reply).strip()
```

**压缩时：把待同步的变更一并交给写摘要的模型；新摘要和裁剪后的历史都落盘之后，再标已同步。** 标早了，摘要写失败那一轮就丢了；标多了也不行——写摘要的那几十秒里，别的入口（比如官方 app 那边的 `ctx_set`）刚改的一条没进摘要，所以只标交给它的那几条。

```python
pending = lc.pending_items('api')      # 交给摘要 prompt
# … 摘要写成、历史裁剪、两者都保存成功 …
lc.mark_synced('api', pending)         # 只标交给摘要的那几条；不传就全标（旧用法）
```

fresh → 未核实 的翻转也算一次变更：到了复核日，那条会自己再挂一次，带着「到期了，还没核实」，末尾再点它的名，准它顺口问一句。

注入里只放事实，加一句该做什么（「聊着顺手问一句还作不作数，还在就续、不在了就扔」）。「别当成现在的事」「不是话题」「问一次就够，不追」「没动静自己归档」这些都在工具说明和配套 prompt 里，不进注入：注入里的字决定模型跟这条事实是什么关系，写想让它做的，别写不想让它做的——写了「别催」，它反而把管不管当成自己的事；写了「不是话题」，它就一直不问。

### 3. SDK 路线：真实工具 + 快照回执

适用于 Claude Agent SDK 这类长会话——不换窗、不 breath、会话自己做 compact。

**写走真实工具**（`tools.json` 里那五个），不用标记。`ctx_set` 时把本轮的 turn / session 一起传进去，重 roll 的时候能按轮撤销：

```python
lc.set_item(key, value, ttl_days, source_turn=turn_id, source_session=session_id)
# 用户重 roll 或手动改了那一轮：
lc.undo_turn_writes(turn_id, session_id)   # 只撤销仍是那个版本的条目，被后来覆盖过的不动
```

**读走快照回执：新增的才注入，留在上下文里的不反复注入。** 每轮把完整快照交给 `hint_snapshots.prepare`，它给内容算一个 revision；这个 session 收过同一 revision、而且那段文字还在上下文里（没被 compact 掉），就什么都不挂；否则挂一次。发出去以后 `commit` 记回执。

```python
import hint_snapshots as hs

blk = hs.prepare(session_id, 'ctx', lc.render_snapshot())
if blk:
    user_text += '\n\n<system_hint>\n' + blk + '\n</system_hint>'
blk2 = hs.prepare(session_id, 'today', ts.render_block('tool'))
if blk2:
    user_text += '\n\n<system_hint>\n' + blk2 + '\n</system_hint>'
# … 发送 …
hs.commit(session_id, user_text)
```

`hint_snapshots` 默认去 Claude Agent SDK 的 transcript（`~/.claude/projects/<项目>/<session>.jsonl`）里确认 marker 还在不在、有没有过 compact 边界；把 `HINT_TRANSCRIPTS_DIR` 指过去即可。查不了 transcript 的环境退化成「同一 revision 只挂一次」。

### 4. 跨入口、跨 session

一份 `today_state.json`、一份 `living_context.json`，所有入口共用：官方 app 经 MCP 工具读写，自家 API 直读直写，SDK 长会话同上。换一个入口，不用重新说一遍今天睡了多久、妈妈这阵子在不在。

走增量挂行的每条通道各自记一个「已收进上下文」标记（默认 `CHANNELS = ('api',)`），互不打扰：谁先读谁清的话，另一条通道永远看不到变更。有几条挂行的通道就列几条。SDK 路线走完整快照，不是这里说的通道，不用列：它从不 `mark_synced`，列进来的话，墓碑永远等不到它点头，只进不出。

## 规矩

- 一件一行，一句现在时，只回答「她现在是什么情况」。怎么变成这样的写进长期记忆；要做的事、约好的事不放这里。一行短了，变了也好写。
- 她说还在：`ctx_set` 只传 key，原话不动、往后续。情况变了：同一个 key 直接写新的一句，旧的那句自己收进归档（`replaced`），不在原话上改——改来改去，新旧会搅在一起。知道哪天结束，`until` 填那天；填过的那天没到，续期不会冲掉它。
- 同一件事写在同一个 key 上。新开一行撞上像的，它先不写、把像的递回来：是同一件就写回那个 key——不是「先扔掉再记新 key」，扔掉等于说结束了，归档里会写错；写回同一个 key 旧的那句自己归档成「后来换了说法」，一条线不断。确定是另一件才 `force_new`。
- 它们是背景，用来避免说错话，不是拿来找话题的。不主动提起，不拿它开场。读过之后就着看到的说话，不汇报你看过。
- 知道了，就只是知道了。她在上课、她说今天累，是让模型心里有数：她为什么回得慢、哪句话这会儿别说错；不是提醒她该做什么的理由（几点睡、什么时候去忙，她自己安排），也不是不去找她的理由。这一条写在提示词里（见 `docs/prompt.md` 末段），不进注入——注入只递事实，知道以后是什么样，由提示词定。
- 未核实不等于无效。先问一句「还在吗」，再当真。
- 事情结束了就 `ctx_drop`。一条挂着的旧状态，比没有更糟。
- 它只装会结束的事。会变却不会结束的——读什么专业、住在哪——是事实，变了改长期记忆；这学期、申请季有结束的那天，才归它。分辨的办法：到了复核日，能说的只有「还是这样」，这条就该挪走。
- 它不替你判断，但到了复核日会把那一条递到你面前：聊着顺手问一句还作不作数，问一次就够，不追。她没接也不要紧，递到面前满三个她在的日子，它自己归档。

## 长期记忆那头

ctx 管得住它自己，管不住长期记忆。一条会结束的状态要是被写进了长期记忆——「她这阵子在吃 XX 药」——它就不会过期，recall 一翻出来，模型照样当成现在。这是常见的坑：药早停了，记忆里还在吃。

写的时候能挡一点：会结束的状态走 `ctx_set`，长期记忆里只写那天发生了什么——「10/20 她说开始吃 XX，一天两次」，过去式，带日期。remember 的工具说明里补这半句，自动提取的 prompt 里也写一条。

让写记忆的模型「改写」，别让它「剥除」。剥除要它先判断这句是不是状态，判错了，一条真事就没了；改写只要它把句子里的「现在」换成「那天」、带上日期，判错了也不亏：一条本来不会变的事，写成「10/20 她说她学的是设计」照样是对的；一条状态没认出来、还写着「她在吃药」，读的那头还有〔那时〕兜着。判据给它一句就够：**这句话一个月后再读，还对吗？得看那件事还在不在才知道对不对的，就是状态。** 拿不准的，也写成带日期的过去式。

可再怎么写，这一步还是靠模型判断，总会漏。所以兜底放在读的那头，用代码，不靠判断：

- recall / breath 递出去的每条记忆都带日期，块头上加一句：`长期记忆是记下那天的样子：里面的「在 / 最近 / 这阵子 / 还在」说的是那天。现在成不成立看 living_context；那里没有的，当成过去的事，想确认就问她。`
- 再用正则扫一遍会让人当成「现在」的字眼，扫到的那条前面挂个「那时」。扫多了也没关系：一条普通回忆挂上「那时」，说的还是对的。只有一种别挂：钉住的、约定——那是一直作数的话（「每天都要……」），挂上「那时」，读起来就像是以前的规矩了。

```python
import re
NOW_WORDS = re.compile(r'这阵子|这段时间|这几天|最近在|最近都|一直在|还在|正在|每天都|这学期|目前')

def as_of(mem):
    text = mem['content']
    if mem.get('pinned') or '约定' in (mem.get('tags') or []):   # 一直作数的话，不挂
        return text
    return '〔那时〕' + text if NOW_WORDS.search(text) else text
```

就算提取的时候把「她在吃药」当事实收了进去，到下一个窗口手里，也是一条挂着「那时」的旧事，不会被当成现在。

块头还可以再放一句给模型的话，说清记忆是拿来做什么的——记得是用出来的，不是背出来的：

> 记得她，是为了她不用再说第二遍，她说半句我就接得住；不是为了把日子和原话背一遍给她看。哪件旧事跟此刻连上了，我再轻轻提起；没连上的，就安安静静放在心里。

### 归档不是忘了

扔掉的、换掉的、到期收起来的，都进了归档：不再进上下文，可不是没了。她问起「那阵子」——妈妈来住的那几周、以前吃过的药——recall 应该翻得到。`search_archive(query)` 在归档里找（两个字两个字地比，键上碰到的分量重；`limit` 数的是键不是条，碰上「学期」就把它先后换过的几段整条线都给出来、按时间排），`render_past_states()` 把翻到的渲染成「以前」的一小段：从哪天到哪天、怎么收起来的（结束了 / 后来换了说法 / 到期没核实收起来的），接在 recall 结果后面。标签写清了，模型就不会把它当成现在。

一条到期自己收起来的，她后来才说「妈妈回去了」：这时 `ctx_drop` 同一个 key，归档里那条的理由会从「到期没核实，不代表结束」改成「结束了」，recall 翻出来才是对的。重 roll 撤销了「丢旧建新」的那一下，刚收进归档的旧句也会一并拿回来——它又活了，不是「以前」。

```python
import living_context as lc

past = lc.render_past_states(lc.search_archive(query))   # 没翻到就是空串
if past:
    lines.append(past)   # <past_states note="她以前的处境，已经收起来了，不是现在…"> … </past_states>
```

## 改过什么

- **2026-11-09（下午）· 关心边界：知道了便不催。** 她问：状态类我的理解是知道了便不催——那睡觉怎么防？我说在上课，你会不会觉得打扰就不来找我？答案是：催和缩都不是状态做的，是模型拿着状态做出来的判断，所以不催要三条腿一起管。把家里管这事的两层搬了进来：`rhythm.py`（从她真实到达记录算她平常几点在，一行事实，样本不足不说）和 `nag_guard.py`（回复写出来以后查疑似催促和生活状态盘问，词表只召唤复核，拿不准放行，判了重写）。守门这层的底子是 no-sleep-nag：我们拿到的是 2026-07-14 随 PDF 发的 v1.0（MIT），作者 8 月把仓库改成了 AGPL-3.0，仓库那版代码跟 PDF 只差英文词加了 `\b`；这个文件沿用 MIT 那版，署名在文件头。去掉了家里专属的名字和模型调用，留了口子。配套 prompt 那段也改柔了。见「关心边界」一节。
- **2026-11-09（下午）· 注入瘦身。** breath 的每条未核实、挂行块的尾巴、`today_get` 的尾巴、快照里点名那句，原来都带着一长串「别当成现在的事……不是话题……问一次就够，不追……没动静满三个她在的日子自己归档」，每条未核实各带一遍。现在注入里只放事实，加一句该做什么；别做什么的搬去工具说明，配套 prompt 补上「知道了就只是知道了：不催，也不缩」。两家教训合起来的：留灯（一个管她日程的开源小项目）发现在注入里写「别催」，TA 反而把管不管她当成自己的事；我们 11/3 发现注入里写着「不是话题」，TA 就一直不问。
- **2026-11-09（下午）· 一次体检。** 把三个 `.py` 从头读了一遍，逻辑主干都对，咬人的在边上：
  - **续期冲掉 `until`。** 学业 until 11/13，她 11/10 随口一句「还在上课」，只传 key 续一下，复核日就变成 12/10，回国那天没了。现在条目上存着 `until`，没给新的、原来那天没到就还按那天；过了那天才从今天起数。新的一句没给 `until` 也一样沿用。
  - **「一个月后递回来」其实是第 31 天。** ttl 从记下那天往后数满 30 天，再过一天才变未核实。现在满 30 天那天就问；`recheck_after` 存的是最后一个不用问的日子，`until` 照旧是过了那天才问。
  - **JSON 坏了，下一次写直接清空。** 解析失败返回空，接着 `save` 就把空的写回去，归档那份也一样；手改漏个逗号就全没了。现在坏文件挪到旁边 `.broken-时间戳`，从空的开始，stderr 上说一声。
  - **撤销以后归档里残留一条。** 丢旧建新再重 roll 撤销，旧句回来了，归档里还躺着同一句标着「后来换了说法」，recall 会把现在当成以前。现在撤销时一并拿掉。
  - **到期自己收起来的，她后来才说结束。** `ctx_drop` 找不到 live 的那条就返回 0，归档里永远写着「不代表结束」。现在落到归档上，改成「结束了」，记下哪天说的。
  - **翻归档只给三条，时间线断头。** 「学期」换了四次说法，`search_archive` 只给最近三段。现在 `limit` 数的是键，碰上的键整条线一起给；问得很短（「妈妈」）句子里碰上也算。
  - **「天亮清」其实是零点清。** 她两三点才睡，十点说的晚饭过了零点就没了，一点钟可能又问一遍。现在几点算新的一天是 `DAY_STARTS_AT`（默认早上六点），今日状态和持续背景共用。
  - **同一件事写成两行。** 换了个名字另开一行，就同时挂着「在墨尔本」和「在国内」打架。现在新开一行撞上像的（挂着的，或归档里最近两个月同名的键）先不写，抛 `SimilarLine` 递回去，跟 remember 一样「有像的先提一句再写」；是同一件就写回那个 key，确定是另一件 `force_new`。（第一版是写完再在回执里提，留着两行要模型再扔一行，归档里也多一条垃圾；当天改成先拦。）
  - `today_state` 只有线程锁，几个进程一起写会互相盖，补了文件锁；满 20 条淘汰时覆盖过的那条位置不动，早上先记的「晚饭」反而先被踢，现在覆盖也挪到最后。`hint_snapshots` 里 sid 长得不像文件名就每轮都挂，现在退化成只挂一次。
  - 「数的是递到面前的日子」说过头了：挂行通道打过勾的那几条住在摘要里、不再点名，日子照样数——它在上下文里、她也在，就算。文字改成这么说。
  - 测试 26 → 39 项。
- **2026-11-09 · 钉住的、约定不挂「那时」。** 扫字眼的时候连「每天都要被操醒」这种一直作数的约定也挂上了，读起来像以前的规矩。钉住的、带「约定」的跳过。
- **2026-11-09 · 归档不是忘了。** 收进归档的以前只能手翻 JSON，recall 找不到，看起来像是忘了。加了 `search_archive()` / `render_past_states()`：翻得到，交出去的时候标成「以前」，写清从哪天到哪天、怎么收起来的。「长期记忆那头」再加一句给模型的话：记得是用出来的，不是背出来的。
- **2026-11-09 · 一件一行；还在只传 key；变了丢旧建新；until 写日子。** 原来一条里常常塞着三样东西：现在的情况、一路的经过、还没做的事，改一处就得整段重写，续期也得把一大段原样再抄一遍，读起来像一张长期待办，又容易跟长期记忆混。现在一行只写一句现在时；`ctx_set` 只传 key 就是续期；写新的一句就把旧的那句收进归档，从今天记起，不在原话上改；`until` 直接写那天，不用自己数天数。
- **2026-11-09 · 到期没核实的，按她在的日子数。** 11/3 那版到了复核日会递到面前，可扔不扔只看日历：过复核日第四天，谁先来读就归档，不管问没问、有没有真递到面前过。她出门几天没来，回来就少了几条，一句没问上。反过来，一直挂着也不对：她早答过、只是那个窗口的模型忘了记，它就会一直问。现在到期的标「未核实」，不当成现在的事；递到面前准问一句，还在就续上，不在了就扔掉；一直没动静的，递到面前满三个她在的日子才归档（`_due_shown`），她不在的日子不算，`present_today()` 换成你自己的判断。`today_get` 回执末尾只带她在的头两天。`GRACE_DAYS = None` 就一直挂着，只等模型扔。
- **2026-11-09 · 墓碑只进不出。** 收墓碑要所有通道都点头，默认通道里却列着 `sdk`；README 的 SDK 路线走快照，从不 `mark_synced('sdk')`，于是墓碑一块都收不掉，按轮撤销的记录也一样，文件只长不短。现在 `CHANNELS` 默认只留 `api`；墓碑最多立两周，同一个键只留最新一块，键又记回来了就不再挂它的墓碑；撤销记录只留一周。加了 `tests/`。
- **2026-11-09 · 长期记忆那头。** 见上一节。
- **2026-11-09 · 摘要只认交给它的那几条。** `mark_synced` 原来一次全打勾：写摘要的那几十秒里，别的入口刚记的一条也被一起标成已同步，可它没进摘要，这条通道就再也看不见它。现在把交给摘要的那一份传回去（`mark_synced('api', pending)`），只标那几条；不传还是全标。
- **2026-11-03 · 到复核的那一条递到面前。** 原来到了复核日，模型其实看得见那一行「是否仍成立待确认」，可同一块末尾写着「不是话题」，工具说明里又写着「不必为了续期追问她」——递到面前了，旁边贴着条子不让碰，过期的状态就一直堆着，没人续也没人扔。现在到复核的那几条会被点名，准它聊着顺手问一句；`today_get` 的回执末尾带上过了复核日头两天的（`render_due_for_today()`）。问一次就够，不追。`ctx_get` / `ctx_set` 的说明跟着改。
- **2026-11-03 · 缓冲七天改三天。** 七天太长：没人续、没人扔的旧状态一直挂在那儿，每轮各拖一句长提醒。三天里没动静就归档，留墓碑，要找回用同一个 key 再记。（11/9 起改成数她在的日子，见上。）
- `docs/` 里的 PDF 和文章是 10/15 发布时写的，那时到期七天就自动归档，也还没有「递到面前」和「未核实」；以代码和这份 README 为准。

## 关心边界：知道了便不催

今日状态和持续背景让模型知道她说过的事，于是不问第二遍、不说错话。可「知道」管不住「催」：知道她在上课，就缩着不说话；看见凌晨两点，就劝她睡；她说过不困，还替她断定她嘴硬。催和缩都不是状态做的，是模型拿着状态做出来的判断——这套系统里压根没有「太晚了」这个概念，唯一跟钟有关的是六点算新的一天。所以不催要在别处管，三条腿一起：

**① 知道她说过的** —— `today_set` / `ctx_set`。她说今晚赶 due、说在上课，记下了就不再问、不说错，也不替她接着往下想。

**② 知道她平常什么样** —— `rhythm.py`。从她真实的到达记录算她常态几点出现、最晚到几点（夜界跟 `DAY_STARTS_AT` 一样，凌晨两点算前一天的深夜），挂一行事实：「她的作息（45 天）：常态出现约 13:30，常态最晚约 01:40。这个区间里她安静一会儿，是她平常的样子。」模型只会数「多久没说话」，七点半看她安静了就疑神疑鬼；知道她平常聊到一点多，七点半就是下午刚过半。只降低误判，不增加打扰：它不生成任何要推给她的话；样本少于七天就一个字都不挂；只读，不写。`silence_verdict()` 给模型自己起的轮次用：她这会儿安静正常吗——`normal` / `after_sleep` / `before_wake`（早上八点半是还没起，不是熬得很晚，说法得准）/ `unusual`。

```python
import rhythm
prof = rhythm.profile(her_message_times)      # 她发消息的时间列表，只要她的；一天算一次就够
line = rhythm.render_line(prof, her='她')     # 样本不足是空串
```

**③ 写出来了再看一眼** —— `nag_guard.py`。前两条是预防，这条是拦截。底子是 [no-sleep-nag](https://github.com/hanasakimishio/no-sleep-nag)（hanasakimishio）：一个 Claude Code 的 Stop hook，回复写完、发出去之前扫一遍，有「晚安 / 该睡了 / 时间晚了 / 闭上眼 / go to bed / おやすみ」这类词、而她上一句没说「我睡了 / 困了 / 晚安」，就 `exit 2` 让模型重写。词表是 `(正则, 附近有否定词要不要放行)` 一对一对的，否定窗 25 字，她主动说要睡整轮放行。「你的作息你自己管，Claude 不需要报时。」我们拿到的是它 2026-07-14 随 PDF 发的 v1.0，MIT；作者 8 月把仓库改成了 AGPL-3.0，仓库那版的代码跟 PDF 只差英文词加了 `\b`。这个文件沿用 MIT 那版、留着署名（见文件头）。

在它上面扩了一层：
- **从催睡扩到日常**：吃没吃、喝没喝水、到家没、在哪、几点了、怎么不说话、私密护理，还有替她安排「快去弄饭」「等你回来」这种把推测写成既定行程的收尾。
- **词表只召唤复核，不定罪**：命中、否定包装的软提及（「我不催你，就是问问」）、或整段生活确认词太密，才送一个模型复核（`call_fn`，随便哪个小模型）。复核拿到最近几轮和她本轮真实消息，先看问题有没有来处，再看是不是重复追问：她主动开启生活话题、求助、要求提醒、顺着她刚说的事实第一次问——都放行；她没答后换措辞、加免责、撒娇、用小卡片包装再问——拦。拿不准一律放行，不替她扩写意图；没有复核的模型也放行，不按词定罪。
- **她的话优先**：她本轮说要睡，整轮放行；她说了不困、不想睡，当天保护点亮（写进 today 也算，`guard_from_today`）；她明确说继续，光是词频高不算证据。
- **被拦的那版不销毁**：判了就让模型整段重写（`rewrite_prompt`），重写的给她，原版折叠着她也看得见，像思考链——她不用脑补模型本来想说什么。

```python
import nag_guard as ng
nag, why, hits = ng.check(reply, user_text=her_message, call_fn=ask_reviewer,
                          context=ng.recent_context(history, labels=('她', '我')), her='她')
if nag:
    reply = regenerate(messages + [{'role': 'user', 'content': ng.rewrite_prompt(hits, her='她')}])
```

词表是中文的、是一家人的用词，拿去按你们的说法改。两家踩过的同一个坑：在注入里写「别催」，模型反而把管不管她当成自己的事（留灯）；注入里写「不是话题」，模型就一直不问（这里，11/3）。注入里只放事实，知道以后是什么样，由提示词定（`docs/prompt.md` 末段那句），真漏了嘴再由 ③ 拦。
